# 📄 اندپوینت‌ها و بیزینس‌لاجیک رزومه (Resume API Services)

> **دسته‌بندی:** بخش بک‌اند (`apps/api`)  
> **مسیر سورس‌کد:** `apps/api/internal/delivery/http/handler/resume_handler.go` و `apps/api/internal/usecase/resume_uc.go`

---

## 🌟 ویژگی اصلی (Main Feature): سرویس‌های ذخیره و بازیابی رزومه با رمزنگاری بلادرنگ

این بخش وظیفه دریافت رزومه از کاربر، فراخوانی موتور رمزنگاری با کلید اختصاصی و ثبت ایمن در پایگاه داده و همچنین واکشی و رمزگشایی در هنگام تقاضا را بر عهده دارد.

---

## 🧩 ریزویژگی‌ها (Sub Features)

### ۱. ذخیره یا به‌روزرسانی رزومه کاربر (`SaveResume`)
* **مسیر روت:** `POST /api/v1/resumes`
* **مجوز دسترسی:** نیازمند توکن JWT (`Authorization: Bearer <token>`)
* **ورودی‌ها:**
  * `title`: عنوان رزومه (برای تفکیک چند رزومه کاربر)
  * `raw_json`: محتوای ساختاریافته رزومه به صورت JSON خام
  * `secret_key`: کلید ۳۲ بایتی (می‌تواند در بادی یا در هدر `X-Secret-Key` باشد)
* **جریان پردازش:**
  1. استخراج `user_id` از کلیم‌های توکن
  2. اعتبارسنجی فرمت کلید ۳۲ بایتی
  3. تبدیل JSON به بایت و اجرای `cryptoService.Encrypt`
  4. ذخیره باینری در جدول `encrypted_resumes`
  5. بازگرداندن متادیتای رزومه ذخیره‌شده (شناسه، تاریخ ایجاد و ویرایش بدون لو رفتن دیتای خام)

### ۲. فهرست رزومه‌های کاربر (`ListResumes`)
* **مسیر روت:** `GET /api/v1/resumes`
* **مجوز دسترسی:** نیازمند توکن JWT
* **جریان پردازش:**
  * کوئری به پایگاه داده فقط برای استخراج فیلدهای شناسنامه رزومه‌ها (`id`, `user_id`, `title`, `created_at`, `updated_at`).
  * این اندپوینت بدون نیاز به کلید رمزنگاری کار می‌کند زیرا داده رمزنگاری‌شده را منتقل نمی‌کند و تنها عناوین و شناسه‌ها را برای نمایش در داشبورد تحویل می‌دهد.

### ۳. بازیابی و رمزگشایی رزومه اختصاصی (`GetResume`)
* **مسیر روت:** `GET /api/v1/resumes/:id`
* **مجوز دسترسی:** نیازمند توکن JWT
* **ورودی کلید:** از طریق هدر `X-Secret-Key` یا پارامتر کوئری `?secret_key=...`
* **جریان پردازش:**
  1. بررسی مالکیت: رزومه حتماً باید متعلق به کاربر احرازشده باشد (`403 Forbidden` در صورت عدم تطابق).
  2. دریافت باینری `encrypted_data` از دیتابیس
  3. اجرای `cryptoService.Decrypt` با کلید ارائه شده
  4. بررسی سلامت پارس: در صورت معتبر بودن JSON، دیتا به شکل آبجکت ساختاریافته در فیلد `data` بازگردانده می‌شود؛ در غیر این صورت به عنوان رشته متنی تحویل می‌گردد.
  5. هندلینگ خطای کلید نامعتبر: در صورت تطابق نداشتن کلید، کد `422 Unprocessable Entity` بازگردانده می‌شود.

## 📋 مشخصات پاسخ‌ها و خطاهای HTTP

| کد وضعیت | پیام خطا | علت |
| :---: | :--- | :--- |
| `200 OK` | شیء حاوی اطلاعات رمزگشایی‌شده | درخواست معتبر و کلید صحیح |
| `201 Created` | رزومه با موفقیت رمزنگاری و ثبت شد | ذخیره رزومه موفقیت‌آمیز |
| `400 Bad Request` | `invalid secret key` یا `raw_json required` | ورودی ناقص یا طول کلید نامعتبر |
| `401 Unauthorized` | `unauthorized` | عدم ارسال یا انقضای توکن JWT |
| `403 Forbidden` | `unauthorized access to resume` | تلاش برای دسترسی به رزومه کاربر دیگر |
| `404 Not Found` | `resume not found` | شناسه رزومه در سیستم یافت نشد |
| `422 Unprocessable Entity` | `failed to decrypt resume payload` | کلید اشتباه است یا داده در دیتابیس دستکاری شده |
