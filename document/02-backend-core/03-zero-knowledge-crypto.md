# 🛡️ موتور رمزنگاری دانایی‌صفر (Zero-Knowledge Cryptography)

> **دسته‌بندی:** بخش بک‌اند (`apps/api`)  
> **مسیر سورس‌کد:** `apps/api/internal/usecase/crypto.go` و `apps/api/internal/usecase/crypto_test.go`

---

## 🌟 ویژگی اصلی (Main Feature): رمزنگاری پیشرفته متقارن AES-256-GCM

ارزش بنیادین مرقع این است که **حتی مدیران سرور و دیتابیس مرقع نیز قادر به خواندن رزومه و اطلاعات خصوصی کاربران نیستند**. اگر کل دیتابیس سرور به سرقت برود، سارقان تنها به مقادیر غیرقابل‌فهم باینری دسترسی خواهند داشت.

---

## 🧩 ریزویژگی‌ها (Sub Features)

### ۱. پیاده‌سازی استاندارد رمزنگاری متقارن AES-256-GCM
در فایل `apps/api/internal/usecase/crypto.go`:
* الگوریتم انتخابی: **Galois/Counter Mode (GCM)** که یکی از سریع‌ترین و امن‌ترین فرمت‌های رمزنگاری تأییدشده با احراز اصالت همزمان (AEAD - Authenticated Encryption with Associated Data) است.
* طول کلید: دقیقاً ۳۲ بایت (۲۵۶ بیت).
* اینترفیس سیستم رمزنگاری:
```go
type CryptoService interface {
    Encrypt(plaintext []byte, key []byte) ([]byte, error)
    Decrypt(ciphertext []byte, key []byte) ([]byte, error)
    GenerateKey() ([]byte, error)
}
```

### ۲. بردار تصادفی یکتا برای هر بار رمزنگاری (Nonce Generation)
* به ازای هر بار رمزنگاری، یک بردار ۱۲ بایتی کاملاً تصادفی و غیرتکراری با استفاده از `crypto/rand` تولید می‌گردد.
* این کار تضمین می‌کند حتی اگر کاربری دو بار یک رزومه یکسان را ذخیره کند، خروجی‌های باینری کاملاً متفاوت بوده و هیچ الگویی قابل شناسایی نیست (مقاومت در برابر تحلیل آماری).
* ساختار خروجی باینری:
  `[12-byte Nonce] + [Encrypted Ciphertext] + [16-byte Authentication Tag]`

### ۳. تایید اصالت و یکپارچگی داده‌ها (Integrity & Tamper-Proofing)
* مود GCM یک تگ ۱۶ بایتی در انتهای داده‌ها ایجاد می‌کند.
* در صورتی که حتی ۱ بیت از داده‌های ذخیره‌شده در دیتابیس دستکاری شود یا کلید کاربر ذره‌ای نادرست باشد، عملیات رمزگشایی بلافاصله متوقف شده و خطای `ErrDecryptionFailed` صادر می‌شود.

### ۴. انعطاف‌پذیری در پذیرش کلید رمزنگاری (Key Flexibility)
در هندلر رسیوم (`apps/api/internal/delivery/http/handler/resume_handler.go`) تابع `parseSecretKey` از سه قالب مختلف برای کلید ۳۲ بایتی پشتیبانی می‌کند:
1. **رشته متنی ۳۲ کاراکتری خام (Raw String)**
2. **رشته ۶۴ کاراکتری Hex (Hex-encoded 32 bytes)**
3. **رشته Base64 انکودشده (Base64-encoded 32 bytes)**

کلید می‌تواند هم از طریق بدنه JSON (`secret_key`) و هم از طریق هدر اختصاصی درخواست (`X-Secret-Key`) یا پارامتر Query String ارسال گردد.
